# FarrierOS Future Roadmap

## Phase 1: Prototype 0

- Local-first responsive PWA prototype.
- Sample data only.
- Core navigation.
- Fluffy demo workflow.
- Verified setup save flow.

## Phase 2: Local MVP

- IndexedDB persistence.
- Installable PWA manifest.
- Service worker for offline app shell.
- Broader horse, barn, and client records.
- Calendar recurring interval handling.
- Data export and backup.
- Stronger photo/document placeholders.

## Hosted Beta Foundation

- Authenticated farrier workspaces.
- Secure cloud records and offline synchronization.
- COIN secure client-onboarding links, review queue, and record import.
- Token expiration, revocation, rate limiting, and intake audit trail.

## Phase 3: Field Workflow Expansion

- Faster finish-job templates.
- Better prep sheet printing/export.
- Route-day work mode.
- More robust due and overdue lists.
- Owner summary draft generation.
- Invoice and payment status placeholders without live payments.

## Phase 4: Controlled Sharing

- Client portal.
- Owner access to approved reports and documents.
- Vet-sharing permissions.
- Farrier-controlled sharing rules.
- Audit trail for shared records.

## Phase 5: Communication And Scheduling

- Appointment confirmation text previews become real integrations.
- Notification preferences.
- Apprentice and business-partner live schedule sharing.
- Real-time update pings for scheduled, removed, rescheduled, and completed horses.
- Reminder workflows.
- Route optimization.
- Optional cloud sync.

## Phase 6: Advanced Hoof And Shoe Prep Tools

- Hoof outline capture.
- Shoe-shape files attached to verified setups.
- Visual comparison across cycles.
- Hardware connection for future shoe-shaping equipment.

## Phase 7: Intelligence With Guardrails

- Pattern detection across service history.
- Prep checklists based on prior work.
- Administrative summarization.
- No AI diagnosis without clear clinical and legal boundaries.

## Architectural Guardrails

- Verified setup history must remain the core record.
- Sharing must be opt-in and controlled by the farrier.
- Cloud features must not break offline field use.
- Hardware integrations should attach to shoe setup records.
- Real payments, SMS, and sync require explicit user consent and configuration.
